## After you change styles

- Lint the style modules you changed and fix every `tasty/*` problem: `tasty-lint:check <files>`.
- In a Cookbook site, the rules see Cookbook's styling helpers and the site's theme names only through a `tasty.config.ts` built with `createValidationConfig(docs.theme)` from `@tenphi/cookbook/eslint-plugin`, as the "Custom components" page shows. Without it, they check nothing in a Cookbook site, and `tasty-lint:check` notes each file it found no styles in. In a Yarn site, the tool and the edit hook also need `eslint` as a dev dependency, which Yarn does not install with Cookbook; without it, the hook lints nothing and says nothing.
- In a Cookbook site that lints through `@tenphi/cookbook/eslint-plugin` or `oxlint.config.mjs`, as the "Custom components" page shows, the tool and the hook do not find that config and run the recommended rules; the tool's last line says which. Add `--strict` when the site's config uses the strict preset, and run the site's own lint command before you finish: its `lint` script, else the `eslint` or `oxlint --config oxlint.config.mjs` command that page shows.
- In a Cookbook site, the rules do not read `theme.styles`, `theme.customStyles` or `theme.recipes` in `docs.config.ts`, and neither `cookbook doctor` nor the build checks their values. Do not lint that file: check each changed object with `tasty:styles`, as the Tasty rule shows.
- Each `tasty/<rule>` has a page in the `tasty-lint` docs index.
